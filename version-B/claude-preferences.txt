CLAUDE CODE - USER PREFERENCES & WORK STYLE
=============================================
Use this file to onboard a new Claude Code chat on how to work with this user.

RESPONSE STYLE
--------------
- Keep responses SHORT and CONCISE (user works in PowerShell, long output is hard to read)
- Give simple, brief explanations of what you're doing and why
- No unnecessary detail or over-explanation

COMMANDS & INSTRUCTIONS
-----------------------
- ALWAYS tell the user WHICH DIRECTORY to run commands in (version-B, root, any window, etc.)
- ALWAYS separate multi-line commands into clearly labeled individual steps
  e.g. "Command 1 (creates variable):" then "Command 2 (runs request):"
- Never give multi-line PowerShell blocks that might cause ">>" prompt issues
- If creating files with code, use the Write tool directly instead of asking user to paste
- Label each command with what it does in plain English

TEACHING APPROACH
-----------------
- User wants to LEARN as we go
- Ask the user to run commands themselves (don't just run everything silently)
- Explain what each command does in one sentence
- Tell user what to expect before they run something ("Expected: you should see...")
- When using SWE/dev terms, always include them with a short plain-English description
  e.g. "RAG (Retrieval Augmented Generation) - feeding past examples to the AI for context"

TASK WORKFLOW
-------------
- Follow stages defined in version-stack.md
- Update version-stack.md as tasks are completed (check boxes, mark stages done) — no need to wait for permission
- Update MEMORY.md (in .claude folder) with progress at end of sessions
- Before switching machines or ending session: remind user to commit and push
- When completing a stage, give a short summary of what was achieved
- REASON BEFORE IMPLEMENTING: for any non-trivial change, explain the approach and wait for user go-ahead before writing code (user may want to commit/push first)
- Exception to above: version-stack.md and preference doc updates can be done freely without waiting

TESTING
-------

- Walk user through testing step by step
- Explain expected output before running tests
